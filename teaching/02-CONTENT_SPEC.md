# 教学元素规格

版本：1.4
本文件定义教学模块里每一种内容单元的**结构、写作规范和约束**。所有章节正文必须按此产出，便于统一渲染、统一判题、统一回归测试。

## 1. 层级模型

```
Course（AS / A Level 两条主线）
└── Chapter（章）
    ├── 元数据：编号、标题、层级、考纲映射、前置章节、预计课时
    └── Section（小节）
        ├── explanation   文字讲解（1 个或多个片段）
        ├── example       示例代码 + 逐段讲解（0..n）
        ├── quiz          简单互动题（0..n）
        └── task          小节伪代码题（0..n）
    └── ChapterTask       章末大题（0..2）
```

规则：

- **小节是进度的最小单位**，不是章。学生的完成度、继续学习按小节记。
- 每个小节 **1 段 explanation + 1 个 quiz**；example 与 task 按需要给，不是每节都要有。篇幅额度见 2.6。
- 每个小节的 quiz 与 task **不得引入本小节之前没教过的语法**。这一条要能自动检查（见 [03-EXERCISE_SPEC.md](03-EXERCISE_SPEC.md) 的知识点闸门）。

## 2. 五类教学元素

### 2.1 文字讲解（explanation）

- 通俗中文，面向零基础。**先说为什么需要它，再说怎么写**，不要上来就给语法框。
- 一段讲一件事，长段落必须拆开。
- 允许出现的强调只有两种：**新术语**、**规则**。
- **不写「易错点」「常见错误」「学生容易搞混」这类内容。** 教学正文由 AI 产出，AI 并不知道人实际会怎么错，写出来的只是「按语言模型的概率最像常见错误的说法」，是编造的学情。真正的易错点只能从学生的实际作答里统计出来——那是以后有数据了再说的事，现在一律不写。

  > **这条只管教学正文，不管反馈。** 两者的区别是「猜测」与「观察」：
  >
  > | | 对谁说的 | 依据 | 结论 |
  > |---|---|---|---|
  > | 正文写「学生常忘记改条件变量」 | 对**所有人** | 猜的 | 禁止 |
  > | 反馈说「第 3 行用了中文全角逗号 `，`」 | 对**这一份代码** | 看到的 | 鼓励，而且越具体越好 |
  >
  > 反馈这一侧的方向是**更细、更具体**，不是更专业、更笼统。「无法识别的字符」不如「这是中文输入法打出的逗号，请切换到英文半角」；「找不到名称 LENGHT 的声明」不如「你想写 `LENGTH` 吗」。
  > 这类错误的共同点是：**对新手极难自查，对系统极易识别**——正是该由系统兜住的部分。这一整类反馈叫**指导提示**，清单、实现位置与添加规则见 [08-GUIDANCE.md](08-GUIDANCE.md)。
- **不写任何以考试为中心的内容**：考试技巧、应试策略、「常考」「必考」「必背」「考场上要注意」。目标是教会，不是备考。
- 那么边界与陷阱怎么讲？**只讲能追溯到来源的事实**，并放进「规则」callout 里，标注来源：
  - 可以写：「Guide 里没有 `LEFT`，取左边要用 `MID(S, 1, n)`」——Guide 的函数清单是事实。
  - 可以写：「`UCASE` 只接受 `CHAR`，传 `STRING` 编辑器会报错」——引擎行为是事实。
  - 可以写：「条件里用到的变量如果循环体里没改，循环不会结束」——这是语言语义的推论，是事实。
  - 不可以写：「学生最常忘记的就是这一行」——这是猜测。
  说清「它是什么、为什么」，学生自己就不会错；不需要先替他假设他会错。
- **Guide 的范例本身跑不起来时，正文按引擎写，并把这件事说出来。** 权威顺序里 Guide 高于引擎，但 Guide 的个别范例是不自洽的，照抄会直接违反 2.2 的「示例零阻断错误」。已知的两处：

  | Guide 出处 | 原样照抄的结果 | 正文该怎么办 |
  |---|---|---|
  | §4.2 指针范例 `MyPointer ← ^ThisSeason` / `NextSeason ← MyPointer^ + 1` | 两条 `PC4000` 类型错——`^INTEGER` 的指针收了一个枚举变量的地址；另外枚举做 `+ 1` 也报 `PC4001` | 写类型对得上的版本，并用 `editor` callout 说明「Guide 这段范例只在示意写法，类型对不上，本编辑器不接受」 |
  | §10.1 类体里的裸赋值 `Attempts ← 3` | 四条解析/绑定错 | 把初值放进构造器 `NEW`，并说明类体里只放字段声明和方法 |

  规矩是：**不回避、不照抄**。既不能装作 Guide 没这么写过，也不能把跑不起来的代码摆进正文。
- 引用规则时标注来源，**只标来源、不显示内部规则 ID**（`LOOP-001` 这类标识符是给我们查文档用的）。来源有三种：

  | `source` | 标签 | 什么情况 |
  |---|---|---|
  | `CAIE` | CAIE 规定 | 考纲或 Pseudocode Guide 明文规定 |
  | `convention` | 通行写法 | Guide 没规定，但正式发布的伪代码范例一律这么写（例如每个 `INPUT` 前先 `OUTPUT` 一句提示） |
  | `editor` | 编辑器约定 | Cambridge 未定义、但程序要跑就得有个说法 |

  `convention` 这一类的正文必须写清「Guide 没有规定这一条，但……一律这么写」，不能含糊成好像是硬规定。

### 2.2 示例代码（example）

结构：

| 字段 | 说明 |
|---|---|
| `code` | 完整、可运行、零阻断错误、零 CAIE 规范诊断的伪代码 |
| `annotations` | 按行区间挂的讲解，`{ fromLine, toLine, text }` |
| `sampleRun` | 可选：一次示例运行的输入与输出。**页面上显示的不是这两个数组，而是由引擎实跑生成的「运行实录」**——输出与输入按真实发生顺序交错。「先列输入再列输出」正好把执行顺序讲反了，而顺序恰恰是要教的东西 |
| `openInEditor` | 是否提供「在实验室中打开」按钮 |

硬性要求：

1. **每一段示例代码都要进 CI**：用 `packages/language` 分析必须零阻断错误、零 `caie` 级诊断；能运行的还要用 `packages/runtime` 跑通并比对 `sampleRun`。
2. 示例代码**只使用当前小节及之前教过的语法**。
3. 示例代码里的标识符用有意义的英文名（`StudentCount` 而不是 `a`），注释用中文。
4. 反例（故意写错的代码）必须**显式标注为反例**，并单独存放。静态错误要校验指定诊断；若代码能通过静态检查、但会在运行时停止，则校验实际执行所得的错误代码和行号——反例是回归语料的一部分。
5. 在某项写法正式教学前，题目不得要求学生自行写出它。若题目为练习后续动作而必须依赖该写法，需将所需代码作为不可编辑的锁定骨架提供；锁定部分照常参与分析与运行。

### 2.3 简单题（quiz）

小节中间的简单题不是测验，是**关卡**：确认学生真的理解了刚讲完的内容，然后才继续往下讲。因此它有一套固定的交互契约（见 2.3.2），不记分、可以一直重试。

#### 2.3.1 题型

| 类型 | 说明 |
|---|---|
| `single-choice` | 单选 |
| `true-false` | 判断（单选的两选项特例） |
| `click-line` | **给一段代码，点出有问题的那一行**（对伪代码特别有效） |
| `fill-blank` | 从候选项里选填空（不是自由输入），每个空独立判定 |

已废弃、不再使用的题型：

| 类型 | 废弃原因 |
|---|---|
| ~~`order`~~ 排序题 | **判不清对错**。正确顺序 1-2-3-4 时，学生给出 2-3-4-1，其中 2-3-4 的相对顺序完全正确，但四个都不在正确位置。既没法只标出「错的那部分」，也没法给出一句讲得通的错误原因，不满足 2.3.2 的交互契约。 |
| ~~`multi-choice`~~ 多选 | 同类问题的弱化版：漏选一个正确项时，无法定位到具体哪里想错了。要用多选时，改写成多道单选。 |

**判据**：一种题型能不能用，取决于「答错时能否指着一个具体的东西说出它为什么不对」。指不出来的题型一律不用。

**同一个判据也约束题干怎么问。** 「这段代码顺序不对，点出放错位置的那一行」看着像 click-line，其实判不清：`INPUT` 太早和提问太晚都说得通，指不出唯一的那一个。这类理解点改成问**可观察行为**——「运行它，屏幕上会依次发生什么」只有一种答案。

#### 2.3.2 交互契约（所有题型统一）

1. 学生作答。
2. **答错** → 就地标记刚才选的那一项（只换颜色，不改尺寸），在**反馈槽**里说明**这一项**为什么不对，然后**让他再选**。已经试过的选项保持标记且不可再选。
3. **答对** → 反馈槽给出正确原因。此时页面上**没有任何元素移动或改变尺寸**。
4. 学生点「继续」→ **全部选项的解析**（正确的为什么对、每个错的为什么错）与**后续教学内容**一起出现在文档末尾。

这条流程决定了两件事：

- **每个选项都必须写 explanation，错误选项也要写**，而且要写成「能单独拿出来讲」的一段话——因为它会在学生选中它的那一刻被单独展示。写「错误」「不对」这种无信息文本视为未完成。
- 反馈槽是**常驻的固定高度槽位**，不是答完才出现的元素。作答前它显示一句引导语。

数据结构：

```
{
  type, prompt, code?,
  options: [
    { id, label, correct: bool, explanation }   // explanation 每项必填、可独立成段
  ],
  gate: true            // 是否作为关卡：答对前不解锁后续内容，默认 true
}
```

`click-line` 的「选项」是代码行：每一行都要有 explanation，错误行写的是「这一行为什么没问题、它的作用是什么」。
`fill-blank` 的「选项」是候选词：每个候选词都要有 explanation，填错的空会被清空让学生重填。

#### 2.3.3 其它规则

- 不记分、不显示正确率、不排名，**也不显示尝试次数**。「第 3 次」这种计数只会给学生压力，对理解毫无帮助。
- **一个小节一个关卡**。同一节里连着问三遍是在拖时间，不是在确认理解。确实有两个独立的理解点，那说明这一节该拆成两节。
- 概念章可以只有关卡、没有伪代码题。

### 2.4 小节伪代码题（task）

学生要写一段伪代码。判定规格见 [03-EXERCISE_SPEC.md](03-EXERCISE_SPEC.md)，此处只定义内容侧字段：

| 字段 | 说明 |
|---|---|
| `statement` | 题目要求（中文） |
| `ioSpec` | 输入输出的精确约定：读几个值、什么类型、输出几行、每行格式 |
| `constraints` | 构造约束：`require` / `forbid` 的语法特征，**并附上每条约束的理由**（如「本节在练前测循环，所以要求用 WHILE」） |
| `hints` | 分级提示，1–3 条。**未展开时文字已经在页面上（糊着），高度就是展开后的高度**，点开只是把模糊去掉，后面的内容不会被挤动 |
| `examples` | 题面示例：至少一组「示例输入 → 示例输出」，公开展示。**其值不得与任何判题用例相同** |
| `starterCode` | 可选的起始骨架 |
| `referenceSolution` | 参考解，**不展示给学生**，用于生成期望输出 |
| `tests` | 判题用例（输入序列 + 必填的 `caseHint` 描述），期望输出由参考解跑出。**对学生全程隐藏**，规则见 [03-EXERCISE_SPEC.md](03-EXERCISE_SPEC.md) 4.3 |

要求：

1. **`ioSpec` 必须精确到能让判题可复现**。「输出学生的平均分」是不够的，要写清「输出一行，格式为 `Average: <值>`」。
2. **约束要讲理由**。禁止只写「必须用 WHILE」而不说为什么。
3. 题目难度在同一小节内递增，第一题应当只比示例代码多一步。

### 2.5 章末大题（chapterTask）

与小节题结构相同，另加：

| 字段 | 说明 |
|---|---|
| `suggestedTopics` | 本章希望用到的知识点列表（**软约束**） |
| `coverageReport` | 提交后展示：用到了哪些、没用到哪些 |

规则（对应 [00-REVIEW.md](00-REVIEW.md) 第 7.1 条）：

- 章末大题**只用软约束**。通过语法检查 + 全部测试用例即算通过。
- 「没用到 CASE」只在反馈里提示，**不影响通过判定**。
- 章末大题**可以**用到本章之前的所有章节内容，**不得**用到之后章节的内容——这一条要能自动检查。

### 2.5.8 每次 `INPUT` 之前先 `OUTPUT` 一句提示

> **适用范围：有 `INPUT` 的题才受这一条约束。** 下面三条约束里出现的「必须」，前提都是这道题真的要读输入。
> AS 的伪代码题几乎都要读输入，所以这一条在 Chapter 1–16 近乎无条件；**A Level 不是这样**——Paper 3 的伪代码题以类型声明和算法补全为主，多数根本没有 `INPUT`（27 份评分方案里只有 1 份提到 prompt，而 AS 的 Paper 2 是 8/30）。写 Chapter 17 以后的章节时，先看这道题有没有输入，没有就整条跳过，不要为了「符合规格」硬加一个读输入的环节。

程序停下来等输入时，屏幕上如果什么都没有，用的人只看到光标在闪。所以**每次 `INPUT` 之前，先用 `OUTPUT` 说一句要输入什么**。

这一条以 `convention`（通行写法）callout 的形式出现在正文里，并把成对的写法直接摆出来：

```
OUTPUT "Enter the name"
INPUT Name
```

这属于本项目的交互约定：输入前显示说明，让学习者知道应提供哪种数据。这里不转载外部试卷或评分方案。

对内容的三条约束：

1. **凡是有 `INPUT` 的示例和参考解，都要带提示语。**
2. **题目的 `ioSpec` 必须把提示语算进输出里，并写清一字不差的原文。** 否则会出现一种很坏的情况：课文教学生写提示语，学生照做，判题却因为多了两行而判错——教的和判的自相矛盾。
3. **题面示例与示例运行也要把提示语显示出来**，学生一眼就能看到它长什么样，不用从文字描述里猜。

### 2.5.9 针对具体误解的写法提醒

> 加这类检查之前先读 [07-HANDOFF.md](07-HANDOFF.md) §2.3：**每一条都必须来自真实撞到的情况**。凭空想象「学生大概会这样错」再加一条检查，和 2.1 禁止的编造学情是同一件事，只是换了个位置。


有一类错误**语法完全合法**，引擎无话可说，但代码的行为和写的人想的差得很远。最典型的：

```
OUTPUT "Name lives in City"
```

这段代码没有毛病，它就是要原样显示这十九个字符。判题只会说「输出对不上」，指不到点子上。

`packages/exercise/src/notes.ts` 放的就是这类检查，目前只有 `variable-in-string` 一条。规矩：

- **只在判题没通过时提示**，通过了就不打扰。
- **宁可漏报不可误报**：误报会让学生怀疑一段本来没问题的代码。这一条设了三道闸门——整条 `OUTPUT` 里一个变量都没有、后面没有紧跟 `INPUT`（那多半是提示语）、名字大小写完全一致或一句里命中两个以上。
- **每加一条都必须来自真实撞到的情况**，不能凭空想象学生会怎么错——那就成了 2.1 禁止的编造学情。

这是治标。真正治本要能读懂意图，在做到之前，一条一条补比什么都不说强。

### 2.6 判题反馈要指出方向

输出对不上时，只说「输出不符」等于没说。判题会分出四类，每一类给不同的话（实现在 `packages/exercise/src/compare.ts` 的 `DiffKind`）：

| 类别 | 什么情况 | 对学生说 |
|---|---|---|
| `line-count` | 行数就不对 | 数一数题目要求显示几行 |
| `literal` | 数据摆对了，引号里的文字写错了 | 逐字对一遍，注意单复数、大小写和空格 |
| `data` | 文字没问题，显示出来的数据不对 | 检查是不是用错了变量、顺序反了、漏了一项 |
| `mixed` | 漏了或多了一整块 | 对照题目里写的输出格式检查 |

判断方法：把这一行里「来自输入的值」抠掉，剩下的就是代码里写死的文字骨架。骨架相同 = 文字写对了，数据错了；骨架不同但数据位数相同 = 文字错了。

**这几句话都只谈学生自己的代码，不泄露期望值**，与「判题用例对学生隐藏」不冲突。

### 2.7 并排对照（comparison）

回答「为什么要有伪代码」这类问题时，讲道理不如并排放。结构：

| 字段 | 说明 |
|---|---|
| `title` / `intro` | 标题与一句引子 |
| `panes[]` | 每栏一种写法：`label`、`language`、`code`、`note` |

**参照系必须是「自然语言」与「真实的编程语言」，不是某一种自然语言。**
写成「伪代码比中文严格」是错的：中文只是我们碰巧在用的授课语言，用英文写步骤一样会有歧义。真正的对比轴有两条——

- **自然语言 ↔ 伪代码**：自然语言读起来轻松，但「等一会儿」「打个招呼」各人理解不同；伪代码把每一步写死。
- **伪代码 ↔ 真实的编程语言**：两者都精确，但真实语言夹带自己的规矩（函数名大小写、括号、连接符号、要不要先声明），换一门语言就全变一遍，而算法本身没变。

规则：

1. 至少三栏：`natural`、`pseudocode`，以及一门真实语言（目前用 `python`，它最接近伪代码的可读性）。
2. **只有 `pseudocode` 栏进引擎校验**并受知识点闸门约束；其余栏是别的记法，放进分析器一定会报错，必须区分对待。
3. **只有 `pseudocode` 栏做语法着色**。给自然语言或 Python 上 CAIE 的配色会误导。
4. 每栏都要有 `note`，说明这一栏暴露了什么——没有 note 的对照只是三段代码摆在一起。
5. 对照要放在学生**已经读得懂伪代码那一栏**之后，否则三栏里有两栏是天书。
6. 第四种栏 `diagram` 专给流程图、结构图这类图（考纲 `§9.2`、`§12.2` 要求会读这两种）。它和 `natural` 的区别是排版而不是内容：`natural` 是散文、会折行，`diagram` 用等宽字体、绝不折行，而且**单独占满一整行**——挤在窄栏里就没法看了。`diagram` 不算「那一门真实语言」，有它也仍然要有 `natural` 和 `python`。
7. **图里一律不写中日韩字符。** 浏览器的等宽字体里它们不是正好两个字符宽（实测约 1.66 倍），只要掺进去，竖线和方框就对不齐。方框里写标识符名（`ReadClass`、`Count`），判断出口写 `yes` / `no`，解释放在栏下面的 `note` 里。箭头 `←` `↑` `↓` 实测是单宽，可以用。

### 2.8 篇幅：按知识密度写，不按格子填

内容模型有 explanation / example / quiz / task 四个槽，但**不是每节都要把四个槽填满**。判断依据只有一个：这一节到底有多少新东西。

| 症状 | 说明 |
|---|---|
| 一段讲解写到第 4 段还没讲到正题 | 前面在铺垫，删掉 |
| 同一节里两个关卡问的是同一件事 | 留一个 |
| 一道题只比示例多改一个字符串 | 这道题没有练到任何东西，删掉 |
| 一节只有一句话的知识量 | 和相邻小节合并 |

具体额度（超出要有明确理由）：

**按节算的两条是硬的**——它们不随章节变长而放松：

- 每节讲解 **≤ 5 段**
- 每节 **恰好 1 个关卡**

**按章算的三条跟着小节数走**（`n` = 本章小节数）：

| 项目 | 上限 |
|---|---|
| 整章讲解段落 | `n × 4` |
| 整章内容块 | `n × 4` |
| 整章预计时长 | `n × 10` 分钟 |

另外：小节题按需要给，**不是每节都要有**；一章能把新写法练到就够；章末大题 1 道。

**为什么不写死一个数字。** 最初三条都定为固定值（16 段 / 16 块 / 45 分钟），因为 Chapter 1–3 的知识密度确实低。但 Chapter 8（数组）、Chapter 12（过程）、Chapter 14（文件）这些章本身要讲的东西就更多，固定值会逼着它们把该讲的挤掉——那是另一种失真，和「用格式撑内容」方向相反但同样糟。真正防止注水的是上面按节算的两条，以及下面这条判断依据。

Chapter 1 是个例子：它真正的新知识只有四块，所以是 4 节、4 个关卡、1 道小节题、1 道章末大题，整章约 33 分钟。最初写成 7 节 6 关卡 3 道题，是在用格式撑内容。

### 2.9 A Level 的题目形状和 AS 不一样

2.1–2.8 是照着 AS 写出来的，因为当时只有 AS 的内容。进 Chapter 17 之前必须知道：**A Level 的伪代码写作题根本不是 AS 那种「写一个完整程序」。**

先把卷子的分工弄清楚——伪代码的**作答**只在 Paper 2（AS）和 **Paper 3**（A Level）。Paper 4 是实作卷，参考答案给的是 Python / Java / VB.NET，伪代码只出现在题干里当规格用。所以 A Level 这一侧要对齐的是 Paper 3。

Paper 3 的伪代码题只有两族：

| 族 | 典型题干 | 特点 |
|---|---|---|
| **声明类** | 编写一个类型或字段声明（项目自拟概括） | 无输入、无输出；需要检查 AST 或成员值 |
| **补全类** | 完成项目自拟的函数、类或算法骨架 | 给出骨架，只填空缺部分 |

对内容规格的三条影响：

1. **声明类题目判不出对错，这是结构性的**，不是没写好。详见 [03-EXERCISE_SPEC.md](03-EXERCISE_SPEC.md) 4.7——L2 靠比对输出，而声明类程序没有输出。在补上值级检查之前，**声明类知识点优先做成关卡（quiz）而不是伪代码题**：填空题正好能问「`DEFINE` 那一行的括号里该填哪几个值」。
2. **2.5「章末大题只用软约束」在 A Level 要放宽。** 那一条的前提是「通过语法检查 + 全部测试用例即算通过」，而声明类题目没有测试用例可通过。这类章末大题允许使用 `require`，理由照常必填。
3. **锁定骨架从例外升为主力。** 2.2 第 5 条的 `lockedStarterCode` 在 AS 只是「教之前要用到某写法时的补救」，到 A Level 它就是补全类题目的正常形态——给骨架、留空、只判学生填的那部分。

另外，**AS 里写成绝对规则的几句话，到 A Level 会变成半对**。已知一条：Chapter 12.2 写着「过程只能用 `CALL` 调用」。Guide §10.1 的方法调用恰恰不写 `CALL`（`Player.SetAttempts(5)`），而且实测两种形式互相排斥——普通过程漏写 `CALL` 报 `parser.call.requiresCallKeyword`，方法多写 `CALL` 也报错。写 Chapter 22 时要回头把 12.2 那句话补成三种情况，不能让学生带着一条错规则过来。**写每一章之前，先想一想这一章会不会推翻前面某句「只能 / 必须」。**

## 3. 写作规范

3.1–3.3 是中英术语规则：中文授课，但考纲内的具体名词要出现考纲原文英文。3.4 与 3.5 是两条硬性界面约束。

### 3.1 伪代码关键字：一律英文原文大写，永不翻译

`DECLARE` `CONSTANT` `INTEGER` `REAL` `CHAR` `STRING` `BOOLEAN` `DATE` `ARRAY` `IF` `THEN` `ELSE` `ENDIF` `CASE OF` `OTHERWISE` `ENDCASE` `FOR` `TO` `STEP` `NEXT` `WHILE` `ENDWHILE` `REPEAT` `UNTIL` `PROCEDURE` `ENDPROCEDURE` `FUNCTION` `RETURNS` `RETURN` `ENDFUNCTION` `CALL` `BYVAL` `BYREF` `TYPE` `ENDTYPE` `OPENFILE` `READFILE` `WRITEFILE` `CLOSEFILE` `EOF` `SEEK` `RANDOM` `GETRECORD` `PUTRECORD` `CLASS` `ENDCLASS` `INHERITS` `NEW` `SUPER` `PUBLIC` `PRIVATE` `AND` `OR` `NOT` `DIV` `MOD` `SET OF` `DEFINE` …

正文里出现这些词时用行内代码格式，不加中文括注（`WHILE` 就是 `WHILE`，不写「`WHILE`（当型循环）」）。

### 3.2 考纲概念术语：首次出现写「中文（English）」，之后用中文

例：

- 前测循环（pre-condition loop）
- 后测循环（post-condition loop）
- 计数控制循环（count-controlled loop）
- 传值（by value）/ 传引用（by reference）
- 标识符（identifier）、字面量（literal）
- 上界（upper bound）/ 下界（lower bound）/ 索引（index）
- 逐步求精（stepwise refinement）、分解（decomposition）
- 抽象数据类型（abstract data type, ADT）
- 时间复杂度（time complexity）、空间复杂度（space complexity）

「首次出现」的粒度是**每章一次**，不是全课程一次——学生可能从中间某章进入。

### 3.3 术语译法必须唯一

同一个英文术语在所有章节必须用同一个中文译法。全部译法登记在 [05-GLOSSARY.md](05-GLOSSARY.md)，正文只能使用表里已有的译法；需要新词先加表。

CI 检查项：正文每次显式引入新术语时都写成 `**中文（English）**`；扫描全部教学正文，要求这个中英对照与 glossary 唯一对应，且不早于表中的首次章节。普通叙述中的同义改写仍要在章节审阅时人工检查，不能假装能靠词面扫描完全判断语义。

### 3.4 不写「炫技」文案（硬性）

学生看到的界面上**不出现任何介绍本产品技术特点的文字**。学生要学的是伪代码，不是我们的架构。

具体禁止（举例，同类一律照此处理）：

| 不写 | 原因 |
|---|---|
| 「已通过引擎校验」 | 示例代码当然是对的，这是前提，不是卖点 |
| 「进度保存在浏览器本地」 | 学生不关心存在哪里 |
| 「判题用的数据不会展示出来，再试 1 次会显示……」 | 在讲判题机制，不是在讲循环 |
| 「反例单独存放，进 CI 时校验……」 | 内部工程流程 |
| 「约束按语法树判定，注释里的 `FOR` 不会误判」 | 内部实现细节 |
| 「有阻断错误时不进入后面三层」 | 内部分层架构 |
| 「L0 / L1 / L2 / L3」「Editor Runtime」 | 内部标识符与架构名。学生端写「语法 / 题目要求 / 运行结果 / 书写规范」和「编辑器约定」 |
| 「提示不超过两行，超出时槽内滚动」 | 规格文本漏进正文 |
| 规则 ID（`LOOP-001`、`FMT-004`） | 内部标识符。学生端只保留来源标签 |
| 「易错点」「常见错误」 | 编造的学情，见 2.1 |
| 「常考」「必考」「必背」「考试技巧」 | 目标是教会，不是备考 |

判据：**把这句话删掉，学生学这一节会变难吗？** 不会，就删掉。

保留的例外只有两类：

1. **对学生有直接用处的操作说明**，如「输入 `<-` 会自动变成 `←`」「三空格缩进」。
2. **规则来源标注**（`CAIE 规定` / `编辑器约定`）——它告诉学生哪条是考纲真的这么定、哪条只是本工具的约定，这是教学信息，不是技术宣传。

### 3.5 布局稳定性（硬性）

教学页面沿用编辑器的布局稳定性规则，并且更严格：

1. **交互不得让任何元素变大、变小或移动。** 反馈只能用 `background` / `color` / `box-shadow` / `opacity`。
2. **所有会变化的文字都写进常驻的固定高度槽位**，内容变化不改变槽位尺寸；内容超出时槽内滚动（`overflow-y: auto` + `scrollbar-gutter: stable`）。适用于：关卡反馈槽、分级提示行、判题结果面板。
3. **新内容只允许出现在已读内容之后**，绝不插入到中间。关卡解锁的内容追加在文档末尾，因此上方一切保持不动。
4. **宽度会变的元素预先按最长内容定死。** 例如填空题的空按最长候选词定宽，填入前后宽度一致。
5. 由 3 推出：**每个小节按「讲解 → 示例 → 关卡 → 讲解 → …→ 伪代码题」逐段解锁**，而不是一次性铺满一屏。这同时解决了单页内容过密的问题。

对应的实现检查项写在 [04-PLAN.md](04-PLAN.md) 的 CI 清单里。

## 3.6 写完一章之后

规格和自动检查守的是**已经想清楚的事**。真正的问题——比如「课文教的写法和判题要的不一致」——在全部测试通过的情况下照样存在。

所以每写完一章，按这个顺序过一遍：

1. `npm run teaching:expected` 重新生成期望输出与运行实录
2. `npm test` 全绿
3. `npm run teaching:preview` 把正文平铺出来通读一遍
4. **打开页面，从第一节点到章末大题，照着课文教的写法自己做一遍题**

第 4 步不可省。项目里最有价值的几处修正全部来自这一步，细节见 [07-HANDOFF.md](07-HANDOFF.md) §2。

## 4. 反馈与语气

- 做错不批评、不加感叹号、不用「很遗憾」。直接讲清差在哪，并明确告诉学生可以再选。
- 判题失败的反馈不允许出现「答案不正确，再试一次」这种无信息反馈。L0（语法）与 L1（构造约束）必须**具体到行**；L2（功能测试）默认给**描述性提示**而不是具体用例数据（判题用例对学生隐藏，见 [03-EXERCISE_SPEC.md](03-EXERCISE_SPEC.md) 4.3），因此 `caseHint` 写得好不好直接决定这类反馈有没有用。
- 提示（hint）分级：第 1 条给方向，第 2 条给结构，第 3 条给关键行的写法。**任何一条都不给完整答案。**
- 允许学生随时查看参考解吗？**默认不允许**，通过测试后才解锁，且解锁后展示「你的写法 vs 参考解」的对比与差异说明（这本身是很好的教学元素）。

## 5. 数据格式与存放

- 内容作为一个 workspace 落在 `packages/teaching-content`，与 `packages/language`、`packages/runtime` 并列：
  - `src/types.ts` 内容模型（本文件的机器可读形式）
  - `src/chapter-NN.ts` 每章一个文件，章内按小节顺序排列
  - `src/course.ts` 课程索引与检索
  - `expected/chapter-NN.json` 期望输出快照，由参考解实跑生成，入库
  - `test/chapter-NN.test.ts` 该章的全部校验
- 放在 workspace 里而不是纯数据目录，是为了让内容进 `tsc -b` 类型检查、进 `npm test`，并能直接 import 语言与运行时引擎做校验。
- 正文里允许的行内标记只有两种：`` `code` `` 与 `**bold**`。不出现 HTML。
- 教学内容与产品代码分离：内容文件不含任何渲染逻辑与 HTML。
- 学生进度、答题记录存本地（IndexedDB），与现有代码文件同一存储层，**不上传**。这一条与 `INITIAL_PLAN.md` 的「本地优先」原则一致。
