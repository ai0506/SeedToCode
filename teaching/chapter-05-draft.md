## 5.1　`FOR … TO … NEXT`：次数已经知道

要把同一句话显示五遍，照抄五行 `OUTPUT` 也做得到。但要显示一百遍呢？要改其中一个字呢？——得改一百处。**重复（iteration）**让同一段代码跑多次，代码只写一份。

次数事先就知道的时候，用 `FOR`：

```
FOR <控制变量> ← <起点> TO <终点>
   <要重复做的事>
NEXT <控制变量>
```

`FOR I ← 1 TO 5` 的意思是：`I` 先取 1，跑一遍循环体；回到 `NEXT` 时 `I` 加 1 变成 2，再跑一遍……直到 `I` 超过 5 就停下来。循环体一共跑 **5** 遍，`I` 依次是 1、2、3、4、5。

起点和终点都算在内，所以 `FOR I ← 2 TO 5` 跑的是 2、3、4、5，共 4 遍——**终点减起点再加一**。

控制变量（control variable）必须是 `INTEGER`，而且和别的变量一样要先 `DECLARE`。`NEXT` 后面重复写一遍控制变量名，`NEXT I`——不写编辑器不会拦，但会提醒你补上，这是 CAIE 的书写习惯。

> **规则**（CAIE 规定）　计数控制循环写作 `FOR <identifier> ← <start> TO <end> … NEXT <identifier>`。控制变量必须是 `INTEGER`，起点与终点都包含在内（Pseudocode Guide §7.1，规则 `FOR-001`）。

**示例：从 1 数到 5**

```
DECLARE I : INTEGER
FOR I ← 1 TO 5
   OUTPUT "Line ", I
NEXT I
OUTPUT "Done"
```

- 第 2 行：`I` 从 1 开始。这一行同时做了三件事——定起点、定终点、说清楚用哪个变量计数。
- 第 3 行：循环体缩进三格。每跑一遍，`I` 的值都不一样，所以五行输出互不相同。
- 第 4 行：`NEXT I` 是一遍的终点，程序走到这里就回到第 2 行加 1 再判断。
- 第 5 行：循环结束之后才执行，只显示一次。

运行实录：

```
Line 1
Line 2
Line 3
Line 4
Line 5
Done
```

**关卡**（单选）　`FOR I ← 3 TO 7` 的循环体一共执行几遍？

- **A**　4 遍
  - ✗ 起点和终点都算在内，别忘了加一：7 减 3 是 4，但 3、4、5、6、7 一共是五个数。
- **B**　5 遍
  - ✓ 对。`I` 依次取 3、4、5、6、7，两端都包含，所以是「终点减起点再加一」。
- **C**　7 遍

- **D**　3 遍
  - ✗ 3 是起点。它决定从哪儿开始数，不决定数多少个。

## 5.2　`STEP`：不是每次都加 1

`FOR` 默认每跑完一遍把控制变量加 1。想换个增量，在后面加 `STEP`：

```
FOR I ← 0 TO 100 STEP 10
```

`I` 会取 0、10、20……100，一共 11 遍。

`STEP` 也可以是负数，这时就是**倒着数**：`FOR I ← 5 TO 1 STEP -1` 取 5、4、3、2、1。倒着数时起点必须比终点大，而且 `STEP` 必须是负的——两者要配套。

如果写成 `FOR I ← 10 TO 1` 而忘了 `STEP -1`，程序不会报错，但循环体**一遍都不会执行**：`I` 一开始就是 10，已经超过终点 1 了。这种循环的特点是「安静地什么都没做」。

`STEP 0` 会被编辑器直接拦下来。增量是 0 意味着控制变量永远不变，循环永远不会结束。

还有一条：**循环体里不要去改控制变量**。`I` 归 `FOR` 管，它每一遍加多少、什么时候停，都由第一行那三个数决定。在循环里写 `I ← I + 1` 能通过检查，但程序跑到那一行就会停下来。

> **规则**（CAIE 规定）　`STEP <increment>` 指定每遍的增量，可正可负，默认为 1（Pseudocode Guide §7.1）。
>
> **规则**（编辑器约定）　`STEP 0` 在运行前就会被拦下（`FOR-002`）；在循环体内修改控制变量会让程序在那一行停止。

**示例：倒数**

```
DECLARE I : INTEGER
FOR I ← 5 TO 1 STEP -1
   OUTPUT I
NEXT I
OUTPUT "Go"
```

- 第 2 行：起点 5 比终点 1 大，配 `STEP -1` 才走得起来。
- 第 3 行：每遍显示当前的 `I`，所以是 5、4、3、2、1。

运行实录：

```
5
4
3
2
1
Go
```

**反例：在循环体里改控制变量**

```
DECLARE I : INTEGER
FOR I ← 1 TO 3
   OUTPUT I
   I ← I + 1
NEXT I
```

这段代码类型全对、结构完整，编辑器一条提示都没有。但它跑到第 4 行就会停：控制变量归 `FOR` 管，程序不允许在循环体里动它。**又一次：能通过检查不等于能跑完。**

想跳着走就用 `STEP`，别自己加。

**关卡**（单选）　`FOR I ← 10 TO 1`（没写 `STEP`）的循环体会执行几遍？

- **B**　1 遍

- **C**　0 遍

## 5.3　`WHILE … ENDWHILE`：先看条件

`FOR` 的前提是次数事先知道。可有些事没法事先知道要做多少遍：一直读数字直到读到 0、一直问直到答对。这时候用 `WHILE`：

```
WHILE <条件>
   <要重复做的事>
ENDWHILE
```

**每一遍开始之前先看条件**：成立就进去跑一遍，跑完回到开头再看一次；不成立就跳过整个循环，从 `ENDWHILE` 后面继续。

因为条件在前面，`WHILE` **可能一遍都不执行**——第一次检查就不成立的话，循环体一次都不会跑。这不是毛病，恰恰是它有用的地方：「一个数都没有」本来就该是合法的情况。

条件里用到的东西，循环体里必须有办法让它变。`WHILE Count < 10` 而循环体里从不动 `Count`，条件就永远成立，程序会一直跑下去（跑得太久编辑器会把它停掉）。

一种常见的写法是**哨兵（sentinel）**：约定一个特殊值表示「到此为止」，比如 -1。要在进入循环前先读一次，循环体的最后再读一次——这样条件每次都是拿最新读到的值去判断。

> **规则**（CAIE 规定）　前测循环（pre-condition loop）写作 `WHILE <condition> … ENDWHILE`。CAIE 的写法里 `WHILE` 后面**不写** `DO`（Pseudocode Guide §7.2）。

**示例：读到 -1 为止**

```
DECLARE Score : INTEGER
DECLARE Count : INTEGER
Count ← 0
OUTPUT "Enter a score"
INPUT Score
WHILE Score <> -1
   Count ← Count + 1
   OUTPUT "Enter a score"
   INPUT Score
ENDWHILE
OUTPUT "Count: ", Count
```

- 第 4–5 行：进循环之前先读一次。不先读，第 6 行的条件就没有值可判断。
- 第 6 行：拿刚读到的值和哨兵比。读到 -1 就结束，-1 本身不算数。
- 第 8–9 行：循环体的最后再读一次。这一句就是让条件下一轮能变的那一句——少了它条件永远成立。

输入 `80`、`95`、`-1` 的运行实录：

```
Enter a score
> 80
Enter a score
> 95
Enter a score
> -1
Count: 2
```

**关卡**（单选）　`Count` 是 10 时，`WHILE Count < 5 … ENDWHILE` 后面跟着 `OUTPUT "Done"`，屏幕上会出现什么？

- **A**　只有 `Done`
  - ✓ 对。条件在每一遍**开始之前**判断，`10 < 5` 第一次就是 `FALSE`，循环体一遍都不跑，直接执行 `ENDWHILE` 后面的那一行。
- **B**　循环体的内容跑一遍，然后 `Done`
  - ✗ 那是下一节 `REPEAT` 的行为。`WHILE` 先看条件再决定进不进去。
- **C**　什么都没有
  - ✗ 跳过的只是循环体。`OUTPUT "Done"` 在 `ENDWHILE` 后面，不归循环管。
- **D**　程序会一直跑下去
  - ✗ 一直跑下去的是「条件永远成立」的循环。这里条件一开始就不成立。

## 5.4　`REPEAT … UNTIL`：先做一次

有些事必须先做一次才知道要不要再做：先问一遍才知道答案对不对，先读一次才知道这个数合不合格。这时候条件应该放在**后面**：

```
REPEAT
   <要重复做的事>
UNTIL <条件>
```

循环体先跑一遍，跑完再看条件。这就是后测循环（post-condition loop）的定义：**至少执行一次**。

`UNTIL` 和 `WHILE` 的方向正好相反，这一点要盯住：

- `WHILE <条件>`：条件**成立**就继续。
- `UNTIL <条件>`：条件**成立**就停。

所以同一件事写成两种循环时，条件往往要反过来写。「继续读，直到读到 -1」写成 `UNTIL Score = -1`；换成 `WHILE` 就得写 `WHILE Score <> -1`。

`REPEAT` 没有 `ENDREPEAT`，`UNTIL` 那一行本身就是结尾。

> **规则**（CAIE 规定）　后测循环写作 `REPEAT … UNTIL <condition>`，条件成立时结束循环（Pseudocode Guide §7.3）。

**示例：问到合格为止**

```
DECLARE N : INTEGER
REPEAT
   OUTPUT "Enter a number from 1 to 5"
   INPUT N
UNTIL N >= 1 AND N <= 5
OUTPUT "Accepted: ", N
```

- 第 2–5 行：不管怎样都要先问一次——不问就没有值可以检查。这正是 `REPEAT` 比 `WHILE` 顺手的地方：不需要在循环前先读一次。
- 第 5 行：条件成立（读到的数落在 1 到 5 之间）就结束。不成立就再来一遍。

输入 `9`、`0`、`3` 的运行实录：

```
Enter a number from 1 to 5
> 9
Enter a number from 1 to 5
> 0
Enter a number from 1 to 5
> 3
Accepted: 3
```

**关卡**（单选）　`Count` 是 10 时，`REPEAT OUTPUT Count UNTIL Count > 5` 会发生什么？

- **A**　什么都不显示，因为 10 已经大于 5
  - ✗ 那是 `WHILE` 的行为。`REPEAT` 把条件放在后面，先跑完一遍才轮到判断。
- **B**　显示一次 `10`，然后结束
  - ✓ 对。循环体先执行一遍，显示 `10`；然后判断 `10 > 5` 成立，于是结束。**条件在后面，所以至少跑一遍。**
- **C**　一直显示 `10`
  - ✗ 一直跑下去要求条件一直不成立。`10 > 5` 第一次判断就成立了。
- **D**　编辑器会拦下来
  - ✗ 这段代码合法。`Count` 在循环里没变，但条件第一次就成立，不会出问题。

## 5.5　前测与后测：同一件事的两种写法

`WHILE` 和 `REPEAT` 都能做「不知道要跑多少遍」的事，区别只在条件放在前面还是后面。把同一个任务用两种写法并排看，区别就很清楚了。

任务：反复读数，读到 -1 为止，数一数读了几个。

*`WHILE` 版本（前测）*

```
DECLARE Score : INTEGER
DECLARE Count : INTEGER
Count ← 0
OUTPUT "Enter a score"
INPUT Score
WHILE Score <> -1
   Count ← Count + 1
   OUTPUT "Enter a score"
   INPUT Score
ENDWHILE
```

> 进循环前要先读一次，否则第一次判断时 `Score` 还没有值。代价是读取那两行写了两遍。

*`REPEAT` 版本（后测）*

```
DECLARE Score : INTEGER
DECLARE Count : INTEGER
Count ← 0
REPEAT
   OUTPUT "Enter a score"
   INPUT Score
   IF Score <> -1 THEN
      Count ← Count + 1
   ENDIF
UNTIL Score = -1
```

> 不用先读，读取只写一遍。代价是循环体里要多一个 `IF`——因为 -1 本身也会被读进来，得挡住它别被数进去。

两种写法都对，但它们在一种情况下**结果不一样**：第一个输入就是 -1。

- `WHILE` 版本：条件一开始就不成立，循环体一遍都不跑，`Count` 是 0。
- `REPEAT` 版本：循环体先跑一遍，读到 -1，靠那个 `IF` 才没有数错，`Count` 也是 0——但如果没写那个 `IF`，`Count` 会是 1，错了。

这就是选择的依据：**「一次都不做」是不是一种合法的情况？** 是的话用 `WHILE`，它天生支持跑 0 遍；不是的话（比如「至少要问一次」）用 `REPEAT`，它天生跑至少 1 遍。

*Python 对照*

```python
count = 0
score = int(input())
while score != -1:
    count += 1
    score = int(input())
```

> Python 只有前测的 `while`，没有对应 `REPEAT … UNTIL` 的写法；要「先做一次」得自己用 `while True` 加 `break` 拼出来。伪代码把两种都作为正式结构提供，所以要自己挑。

**关卡**（单选）　哪一种情况**必须**用 `REPEAT`，用 `WHILE` 会别扭？

- **A**　把一个数组从头到尾走一遍
  - ✗ 次数事先就知道，这种情况连 `WHILE` 都不是首选，`FOR` 才是。
- **B**　反复要求用户输入密码，直到输对为止
  - ✓ 对。不问一次就没有密码可以检查。用 `WHILE` 也做得到，但必须在循环前先问一次，那一段会重复写两遍。
- **C**　只要还有钱就继续买东西
  - ✗ 一分钱都没有时应该一次都不买。「可能 0 次」正是 `WHILE` 的场合。
- **D**　显示 1 到 10
  - ✗ 次数已知，用 `FOR`。

## 章末大题：分数统计｜`5.T1`

写一段伪代码：反复读入分数，读到 -1 表示输入结束，然后显示这批分数的统计结果。

**输入**：若干行，每行一个 `INTEGER`。每次读取之前都要显示提示语，一字不差：`Enter a score`。读到 -1 表示结束，**-1 本身不算一个分数**。

**输出**：

- 如果一个分数都没读到（第一个输入就是 -1），只显示一行：`No scores`
- 否则显示三行：

```
Count: <个数>
Highest: <最高分>
Average: <平均分>
```

平均分取整数商（用第 3 章的 `DIV`）。每个冒号后面都是一个空格。

**建议用到**：`WHILE`、`IF`、`ELSE`、比较运算、`DIV`、`INPUT`、`OUTPUT`。

**提示**：
1. 「一个分数都没有」是一种合法情况，5.5 的判据直接给出了该用哪种循环。
2. 个数、总分、最高分都要一路攒着，三个变量都要在循环开始前先给初值。
3. 求最高分不需要记住所有分数：每读到一个就和目前的最高分比一下，比它大就换掉。
4. 输入结束之后才知道有没有读到东西，所以「`No scores`」这个判断要放在循环后面。

**示例**：依次输入 `80`、`95`、`60`、`-1`，显示

```
Count: 3
Highest: 95
Average: 78
```

依次输入 `-1`，显示

```
No scores
```
