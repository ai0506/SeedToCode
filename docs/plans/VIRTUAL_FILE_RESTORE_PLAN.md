# 运行时虚拟文件单次恢复计划

## 1. 目标与边界

在 Lab 的运行时虚拟文件（`.txt` 文本文件与 `.dat` 随机记录文件）上提供一次、按文件独立的“恢复上一次内容”能力。它用于纠正一次已经保存的内容改动，不是版本历史、跨设备同步历史、撤销/重做系统，也不作用于伪代码源文件。

当前文件内容是逻辑上的 **slot 2**；其恢复前内容是可空的 **slot 1**。实现不复制一份 slot 2，避免当前文件和一份冗余副本发生漂移。

```text
初始/无恢复点： previous = 空，current = 文件当前内容

成功修改：       previous = current（修改前）
                current  = 修改后内容

恢复一次：       current  = previous
                previous = 空
```

因此恢复后不能“恢复回来”；随后再成功修改时，刚恢复出的 `current` 又成为新的 `previous`。这正是每个文件两个逻辑 slot 的限制。

## 2. 明确的产品语义

### 2.1 什么能恢复

- 新建或导入的文件刚出现时没有 `previous`，恢复按钮不可用；这表示没有更早的内容可回到。
- 新建或导入的文件在**第一次成功修改**后，可恢复到它刚新建或刚导入时的内容；“不能恢复新建/导入文件”不应被实现成永久禁止，否则用户修改过内容后仍无法回到刚导入的原文，语义难以理解。
- 当前 Lab 中可原地编辑的是文本文件的 `lines` 与随机记录文件的 `records`。恢复点保存该文件的完整可编辑内容（含 `kind`、`recordType`、`lines` 或 `records`），但保留稳定 `id` 和当前 `name`，避免改变同步实体身份或制造名称冲突。
- 一次成功的本机运行若提交了运行时文件变更，也按每个实际变化的既有文件建立各自恢复点；运行失败或停止时运行时已经回滚，不建立恢复点。

### 2.2 不在第一期范围内

- 删除运行时文件仍是不可撤销操作；删除时一并清除该文件的恢复点。
- “重置运行时文件”是会增加、删除并整体替换文件的批量操作，不能用单文件两个 slot 正确表达；第一期保持其不可恢复语义，不把它伪装成可恢复。
- 不提供多步历史、恢复后的 redo、已删除文件恢复、源代码文件恢复或云端版本浏览。

## 3. 本地、云端与账户边界

恢复点是设备本地的项目元数据，以 `projectId/fileId` 关联；它随本地项目快照持久化并在刷新、关闭再打开、项目切换后保留。旧项目没有该字段时按空恢复点迁移，不改变其已有文件。

恢复点绝不进入 `cloudFilesOf()`、同步队列 payload 或服务端文件内容。用户点“恢复”后，恢复出的**当前文件内容**照常走已有的本地保存与 runtime 文件同步；另一台设备不会得到“可恢复按钮”，只会在同步完成后得到恢复后的文件内容。

远端拉取或冲突合并实际替换本机同一 runtime 文件内容时，清除该文件的本地恢复点。否则一个旧的本机 slot 可能对着已变更的远端版本恢复，制造意外回写或同步冲突。远端冲突副本使用新文件 id，因此天然没有旧 slot。

恢复点是额外本地数据，不能妨碍新内容保存：若浏览器无法持久化恢复元数据，新的当前内容仍按现有路径优先保存；界面必须明确本次没有可恢复点，不能假称已保存恢复版本。

## 4. 修改与恢复的原子顺序

所有入口经过一个共享的“替换既有 runtime 文件内容”操作，不允许编辑弹窗、本机运行结果和恢复按钮各自直接改数组。

1. 找到同一 `projectId/fileId` 的当前文件；不存在则失败，不创建恢复记录。
2. 深拷贝并比较修改前、后的可编辑内容；完全相同则不写恢复点、不产生同步操作，也不给出“已保存恢复版本”的提示。
3. 有变化时，将修改前内容写入 `previous`，再写入新的当前内容，最后走现有 `save()` 与同步入口。
4. 恢复时先读取 `previous`；不存在则不改变文件。存在时将其写回当前内容、清除 `previous`，再走同一保存与同步入口。
5. 所有写入完成后才刷新文件列表、预览和“恢复”按钮状态；失败时保持内存、持久化状态与界面提示一致。

恢复 UI 放在运行时文件的查看/编辑界面内，而非列表上临时出现一颗会挤动布局的按钮。无恢复点时保留固定位置的不可用控件和说明；使用现有应用内确认/提示组件，不新增浏览器原生交互 UI。

## 5. 测试与验收

### 5.1 必须的纯逻辑测试

- 文本与随机记录文件：保存一次、恢复一次、恢复后不可再次恢复、恢复后再次修改建立新的恢复点。
- 内容无变化的保存不产生恢复点；JSON 记录编辑校验失败不改变当前内容或 slot。
- 新建/导入文件初始不可恢复，但首次成功修改后能恢复到初始内容。
- 删除、重置、远端更新和远端删除清除相应恢复点；远端冲突副本不继承原文件恢复点。
- 旧快照没有恢复字段时能读取；恢复元数据绝不出现在 `cloudFilesOf()` 或同步 payload。

### 5.2 浏览器验收

至少新增一条 Lab 浏览器级回归：编辑既有 `.txt` 文件并保存 → 刷新页面或切换项目再回来 → 恢复 → 本机运行读取到恢复后的内容 → 恢复控件变为不可用。随机 `.dat` 文件另做一条 JSON 记录案例。

在窄屏下验证恢复控件不改变列表项、弹窗标题或其他控件的位置；IME 不涉及该文件编辑 textarea，但仍不以此功能替代 Lab 的既有手工编辑器验收。

## 6. 实施顺序

1. 先修正 `web/README.md` 的 Advanced runtime 文档漂移。
2. 提取并测试共享的 runtime 文件内容替换/恢复点逻辑。
3. 接入编辑弹窗与本机运行提交路径，补本地持久化、同步与远端更新清理。
4. 完成上述浏览器回归与窄屏实际检查，再交付 UI。

这项功能可以在完整 Lab E2E 套件之前实施，但它自身的纯逻辑、持久化/同步和最小浏览器回归是交付前置条件。
