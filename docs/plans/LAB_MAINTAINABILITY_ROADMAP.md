# Lab 可维护性与回归路线

## 定位

本文记录 2026-09 对 Lab 维护风险的只读观察，以及据此确定的工作顺序。它不是当前能力清单，也不表示其中的测试或重构已经实施；当前事实仍以 [`PROJECT_STATE.md`](../../PROJECT_STATE.md) 为准。

## 已核实的观察

1. `web/js/app.js` 为 124,467 bytes、2,976 行，集中处理项目与文件、编辑器呈现、诊断、本机运行、trace table 和 Lab 浮层。近期 trace、选区与窄屏改动也集中在此处。它已经是高摩擦改动面，但文件体积本身不足以证明应立即机械拆分。
2. `packages/runtime/src/interpreter.ts` 为 110,572 bytes、2,064 行。它同时包含执行、帧、赋值、虚拟文件、trace 和运行时值模型；其中的行为共享内部状态与时间顺序，直接按主题搬移文件可能只会把私有耦合改成更难维护的接口耦合。
3. `CAIEStorage`、旧 `localStorage` 兼容快照与 IndexedDB entity 已并存。页面完全由 IndexedDB entity 读取仍是 Planned。这是一个应持续留意的迁移边界，不等于已经发现数据错误，也不应在没有迁移验收方案时仓促切换。
4. 自动化测试覆盖语言、运行时、存储、同步队列、判题和前端静态规则；`tests/frontend-rules.test.ts` 明确说明布局几何必须由真实浏览器测量，当前没有 Lab 的浏览器 E2E 套件。IME 合成输入同样不能由一般浏览器自动化替代真实手测。
5. 文档有一处确定漂移：[`PROJECT_STATE.md`](../../PROJECT_STATE.md) 将 Advanced runtime 的 Enum、Pointer、Set、OOP 标为 Complete，但 [`web/README.md`](../../web/README.md) 仍将它们列为“尚未实现”。

## 已确定的顺序

### P0：修正文档事实

单独修复 `web/README.md` 的 Advanced runtime 状态，不把它和代码重构捆绑。修复时应保留仍未完成的单步、断点及 trace 表字段/文件读取/分段表头范围。

### P1：少量高价值的 Lab 浏览器回归

先建立可在本地预览中重复运行的浏览器级测试，不追求覆盖全部 Lab。第一批只锁住确定且可重复的用户路径：

1. 项目切换后保存并本机运行；
2. 查找；
3. trace table 的打开与放大。

第二批再加入需要真实布局引擎的契约：窄屏无 `body` 横向溢出、编辑器滚动同步和选区层位置。几何测试应只断言被操作区域及其固定布局契约，避免用脆弱的全页像素快照代替行为断言。IME 保留清晰的手工验收步骤。

### P2：按功能边界重构 `app.js`

不为减少行数单独重构。当一个新 Lab 功能拥有独立状态生命周期、DOM 区域和可单独测试的行为时，才沿该边界抽离。候选边界是：项目/文件控制、编辑器视图（行号、高亮、选区、查找）、运行与 trace 视图、共用浮层；实际抽离前先写出状态所有权和对外事件，避免把共享全局状态换成隐性跨文件耦合。

AI 助手并不自动等于 `app.js` 的抽离理由：它还涉及跨页面、服务端权限、额度与内容安全边界，应根据最终交互归属决定实现位置。

### P3：由单步/断点需求驱动 runtime 重构

不单独进行“把 `interpreter.ts` 拆小”的外观重构。现有执行控制器已支持输入暂停、停止、事件流与让出执行；单步和断点缺少的是语句边界的暂停调度契约：暂停原因、继续条件、断点命中、调用栈与变量快照时点，以及可重复恢复。

开始该功能时，先为上述契约补运行时行为测试，再根据暴露的边界逐步抽离值快照/克隆、trace collector、虚拟文件操作或表达式求值。是否演化为完整状态机应由恢复语义决定，不预设整体重写。

## 非目标

- 不把“存储仍有兼容层”表述为已确认的同步缺陷。
- 不以浏览器 E2E 取代 IME、复杂选区和真实视觉稳定性的手工验收。
- 不以文件体积作为重构完成或设计健康的判据。
